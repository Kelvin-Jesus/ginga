# Ginga: guide for agents

Ginga turns a Samsung Galaxy tablet (reference: Tab S11, SM-X730) into a real extended display for an Apple Silicon Mac: a virtual display macOS treats as genuine, captured with ScreenCaptureKit, HEVC-encoded with VideoToolbox, streamed over USB (direct/AOA or adb) or Wi‑Fi, with touch, S Pen and keyboard sent back. Two apps: `mac/` (Swift 6, SwiftPM) and `android/` (Kotlin, Gradle). One wire protocol: `protocol/PROTOCOL.md`.

Read before changing anything: this file, then `docs/status.md` (what is done), `docs/known-issues.md` (what bit us, and the rules that came out of it), and the `CLAUDE.md` of the side you touch (`mac/CLAUDE.md`, `android/CLAUDE.md`).

## Commands

```sh
# Mac (Command Line Tools are enough; Xcode not required)
cd mac && scripts/test.sh                 # all Swift tests (swift-testing); ~15 s
cd mac && scripts/test.sh --filter Streaming
cd mac && swift build -c release          # compile check without touching the app bundle
cd mac && scripts/build-app.sh            # build + sign mac/build/Ginga.app and mac/build/ginga (see "Signing")
cd mac && swift build --product ginga && .build/debug/ginga protocol-vectors --out ../protocol/test-vectors   # regenerate golden vectors (no signing needed)

# Android (JDK 17 from Homebrew; there is no system Java)
cd android && JAVA_HOME=/opt/homebrew/opt/openjdk@17 ./gradlew test assembleDebug
scripts/docker-android.sh                 # the same in a linux/amd64 container (Rosetta on Apple Silicon; ~4 min cold)

# Both, plus the protocol contract
scripts/check-all.sh                      # = CI: Swift tests, vectors, private-API grep, release build, Android tests + APK
scripts/setup-release-signing.sh          # once, by the user (asks a password): release keys + GitHub secrets
                                          # releases: push a tag vX.Y.Z → .github/workflows/release.yml (docs/development.md › Releases)
scripts/check-power.sh                    # opt-in, real hardware: bench-power vs docs/power-baseline.json

# Environment
scripts/bootstrap.sh                      # reports what's missing (toolchains, adb, SDK); --install uses Homebrew
```

## Invariants (break one only with a new ADR)

1. **The protocol is the contract.** Any wire change: `PROTOCOL.md` first, then both sides, then `ginga protocol-vectors`, then both suites. Vectors are append-only. New message types after 1.0 are IGNORABLE.
2. **Power is an acceptance criterion** (the reference is Sidecar). Nothing runs when nothing changes: no polling timers, capture only while a consumer needs it, sampling only while a window shows it. Judge pipeline changes by energy (`ginga bench-power`, `ginga energy`), not only latency.
3. **Latest frame wins; encoded frames are never dropped** (backpressure before encoding). No periodic keyframes.
4. **Trust:** adb connections need the loopback token; direct USB only for approved serials; Wi‑Fi needs pinned certificates (pairing with commitments). Input and CONFIGURE are ignored until a session streams.
5. **The private API stays in `CGVirtualDisplayShim`**, runtime-verified, never crashing.
6. **Swift 6 strict concurrency.** Ordered work goes through `DispatchQueue.main` (FIFO) or chained tasks, never separate `Task`s; blocking calls on dedicated queues; every `@unchecked Sendable` says why.
7. **Pure logic is unit-tested without I/O** (interpreters, cadence, bitrate, pairing exchange, direct-link session); I/O wrappers stay thin.
8. **Docs move with the code**: status, known issues, the doc of the area you touched, PROTOCOL.md for wire changes.

## Never do

- Change another monitor's display mode, even `.forSession` (WindowServer persists it per display set; see known issues).
- Change macOS or tablet system/security settings, grant permissions, or enter passwords or the tablet's PIN. Ask the user.
- Switch the Mac's Wi‑Fi network except through the user's explicit "Connect directly" action.
- Overwrite the user's `~/Library/Application Support/Ginga/config.json` with tests or experiments: pass `--config <scratch file>`.
- Run `scripts/build-app.sh` while nobody can answer a keychain prompt (it falls back to ad-hoc signing, and that build loses the Screen Recording grant). Use `swift build -c release` to check compilation.
- Bundle Google's adb; expose the loopback listener beyond 127.0.0.1; log tokens, keys, passphrases or codes.
- Commit, push or create branches unless the user asks. Remote: `github.com/Kelvin-Jesus/ginga` (public, branch `main`); commits end with the co-author trailer.

## Working on the device

- Tablet over adb: serial `R52Y80EE15V`. It locks quickly (PIN): ask the user to unlock; `adb shell dumpsys window | grep isKeyguardShowing`.
- The harness's terminal has no Accessibility grant: CGEvents it posts are dropped. Move the Mac pointer through the tablet (`adb shell input tap/swipe`, `input stylus swipe` in the stream view). `input` can't hover a stylus or do two fingers.
- Launch test configurations without saving: `open mac/build/Ginga.app --args --background --config <file>`; logs with `/usr/bin/log show --predicate 'subsystem == "dev.ginga"'` (zsh's `log` is a builtin).
- Tablet logs: `adb logcat | grep Ginga/`.

## Two agents

Work is often split: one agent on `mac/` + `protocol/`, one on `android/`. The Mac side owns `protocol/` and the vectors; the Android side reports spec gaps instead of editing it. Hand over with the exact PROTOCOL.md sections and the vector names.
